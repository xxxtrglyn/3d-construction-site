# Data Model: Multiplayer World with Host Crews

**Feature**: 002-multiplayer-core | **Date**: 2026-11-04

Where each entity lives:

- **Pure rule functions and types** are in `packages/shared`, with unit tests.
- **The authoritative runtime state** is owned by the server room (`WorldRoom`).
- **The synced view** reaches clients in two ways (see `contracts/network-protocol.md`):
  - Colyseus schema patches for low-frequency state;
  - binary snapshots for worker transforms.
- **The persisted state** is in SQLite (see `contracts/persistence.sql`).

Feature 001 entities (`PieceTypeDef`, `Blueprint`, `StageDef`, `TowerProgress`) are reused unchanged.

---

## GuestProfile (client, device) — extends 001

| Field | Type | Rule |
|---|---|---|
| name | string | from `generateName()`, must pass `isValidGuestName` |
| hatColor | HatColorId | fixed palette |
| muted / hintsDone | as in 001 | |
| **playerKey** | string (32 hex chars, 128-bit random) | new. Created once with `crypto.getRandomValues` and never shown. This is the spec's "reconnect token" |
| **lastWorld** | number \| null | new. The world joined last; used to rejoin after a reload or server restart |
| **hideAllChat** | boolean | new. Default false; hides all typed chat (FR-064) |

- **Storage**: `localStorage` key `hht.profile.v2`. The loader migrates v1 by adding the two new
  fields.
- **Storage unavailable**: there is a fallback to an in-memory profile, as in 001. Resuming after a
  reload then does not work, but the game still plays.
- **On the server**: the server keeps only `keyHash = SHA-256(playerKey)`. The raw key is never
  stored or broadcast.

## SiteLayout (shared, generated static data)

This file is generated by `tools/blender/builders/site.py`, which exports `packages/shared/src/site.gen.ts`
alongside `site.glb`. It is the single source of truth for both the client and the server.

| Field | Type | Notes |
|---|---|---|
| playRadius | number | circular playable area; the controller clamps workers inside it |
| plaza | { center, radius } | safe zone; contains `spawn` and `foreman` |
| spawn | Vec3 | |
| foreman | { pos, yaw, talkRadius } | the talk radius is about 2.0 m |
| plots | PlotDef[12] | index 0–11 |
| supplyYards | RackDef[] | 4 yards × 7 racks, each yard shared by 3 neighboring plots |
| obstacles | { boxes: Box[], cylinders: Cyl[] } | each has a height (`top`), used by the controller |

Each `PlotDef` has:

- `index`, `center`, `yaw`;
- `buildZoneRadius` (3.0);
- `bin` { pos, radius 0.9 }, the supply bin;
- `sign` { pos }, the plot sign;
- `towerFootprint` { hx, hz }, which blocks movement once stage ≥ 1.

## WorkerState and MoveInput (shared kinematics)

`stepWorker(state, input, dt, site, dynamicBlockers) → state` is a pure, deterministic function that
both the client (prediction) and the server (authority) run at a fixed **60 Hz**.

| WorkerState field | Type | Notes |
|---|---|---|
| x, y, z | number (m) | feet position |
| vx, vy, vz | number (m/s) | |
| facing | number (rad) | turns toward the movement direction (no trig in the step: precomputed lookup) |
| grounded | boolean | |
| coyote, jumpBuffer | number (s) | timers ported from the 001 controller |
| carrying | PieceTypeId \| null | applies `carrySlowdown` for beams and bells |

| MoveInput field | Type | Notes |
|---|---|---|
| seq | u16 (wraps) | increases by one per 1/60 s step |
| dx, dz | i8 (−127…127) | world-space wish direction; the client already resolves it relative to the camera |
| run, jump | bit flags | |

The step has these properties:

- **Same feel as 001**: the acceleration (grounded 40, in air 12), coyote time, jump buffer, gravity
  22 and jump apex 1.1 m are the same as 001's character controller.
- **Collision**: the worker is a circle of radius 0.32 m tested against boxes and cylinders.
  - An obstacle with `top` ≤ 0.35 m is stepped onto (autostep).
  - Other obstacles block, unless the feet are already above `top`, in which case the worker stands
    on them.
- **Workers vs. workers**: no worker–worker collision (FR-012).
- **No tunnelling**: at the maximum speed (5.5 m/s ÷ 60), one step moves about 9 cm, which is less
  than the radius.
- **Validation (unit tests)**:
  - the same inputs give bit-identical states;
  - the worker never leaves `playRadius`;
  - it never ends inside a blocking obstacle;
  - horizontal speed ≤ `runSpeed`;
  - the jump apex ≤ 1.1 m above the support surface.

## PlayerSession (server; partly synced)

| Field | Synced? | Notes |
|---|---|---|
| sessionId | yes | public id |
| netId | yes | u16 index used in snapshots; increases monotonically per world and is never reused within a shift epoch |
| keyHash | no | |
| name | yes | `uniqueName(base, taken)` adds " 2", " 3"… to duplicates (stays ≤ 20 chars; see shared `names.ts`) |
| hatColor | yes | |
| worker | snapshot only | authoritative `WorkerState` plus the input queue and `lastSeq` |
| held | yes (`heldType`) | pieceId \| null |
| crew | yes | { plotIndex, role: 'host' \| 'member' } \| null |
| pendingRequest | no (the target Host gets it as a card) | JoinRequest \| null |
| deniedUntil | no | Map<plotIndex, time>, 60 s cooldown |
| deliveredThisShift, donatedThisShift | no (sent in the summary) | counters |
| joinedAt | no | chat unlocks at joinedAt + 60 s |
| recentChat | no | ring buffer of the last 5 accepted messages { text (sanitized, unmasked), channel, at } used for reports; memory only |
| lastChatNorm | no | map of normalized text → time, used for the 30 s duplicate rule |
| reportedThisShift | no | set of keyHashes this player has reported in this shift (one report per target per shift) |
| lastInputAt | no | idle timers: 5 min for Host handover, 10 min for removal from the world |
| buckets | no | rate-limit token buckets (see `RateLimiter`) |
| strikes | no | invalid or over-limit actions counted in a sliding 10 s window |
| state | no | `active` \| `away` (disconnected, within the 60 s grace period) |

**State transitions**:

```text
(join) ──► active ──(socket drops)──► away ──(reconnect ≤ 60 s or join with same keyHash)──► active
                                       └──(60 s)──► gone (crew leave rules apply; held piece dropped)
active ──(consented leave / 10 min idle / kicked for strikes)──► gone
```

## Plot and Building (server; synced; persisted)

| Plot.state | Meaning |
|---|---|
| `free` | no building; it can be assigned by the Foreman |
| `building` | has a Host and a crew; the tower is in progress |
| `unattended` | the tower is in progress, but the crew has been empty for ≥ 3 min; it can be adopted through the Foreman |
| `finished` | Masterpiece; `finishedAt` is set and the crew has dissolved; the sign says "Built by ⟨Host name⟩'s crew" |

| Building field | Type | Notes |
|---|---|---|
| plotIndex | 0–11 | |
| blueprintId | 'clock-tower' | |
| progress | TowerProgress | changed only by `deliver()` |
| hostKeyHash, hostName | | |
| crew | Crew | |
| joinMode | 'ask' \| 'open' \| 'solo' | defaults to 'ask' |
| flag | 0–11 | equals `plotIndex`; 12 distinguishable flag color/symbol pairs |
| emptySince | time \| null | when the last member left; drives `building → unattended` |
| finishedAt | time \| null | |
| bin | BinEntry[] (≤ 10) | { pieceType, donorKeyHash } |

**State machine** (pure functions in shared `plots.ts`):

```text
free ──startBuilding(player)──► building
building ──last member leaves──► (emptySince set) ──3 min──► unattended
building ──member rejoins while emptySince──► building (emptySince cleared)
unattended ──adopt(player)──► building (progress kept, new Host)
building ──deliver()==masterpiece──► finished (after the 8 s celebration the crew dissolves)
finished ──needed for a new building && now − finishedAt ≥ 10 min (oldest first)──► free (retire)
any ──shift reset──► free
```

The Foreman assigns the lowest-index `free` plot. If none is free, it retires the qualifying
`finished` plot with the oldest `finishedAt`. If neither exists, the result is `allPlotsBusy`.

## Crew and JoinRequest (shared `crew.ts`, pure)

**Crew**: `{ members: { keyHash, sessionId|null, name, joinedAt, role }[] }`, at most 8 members
(`CREW.maxSize`).

**Rules**:

- `canSnap(player, building)`: the player is a member of that building's crew.
- `nextHost(crew, now, activity)`: the member with the oldest `joinedAt` who is active (not away and
  not idle ≥ 5 min); otherwise the oldest member.
- Handover triggers:
  - the Host has been away for more than 60 s;
  - the Host leaves;
  - the Host is idle for 5 min while another member is active;
  - the Host makes an explicit `handOver(to)`.
- `remove(member)` is Host only. The removed player gets a 60 s cooldown before asking that Host
  again.

**JoinRequest**: `{ requesterSession, plotIndex, sentAt, status }`

```text
pending ──approve──► approved (requester joins; checks capacity again at approval time)
pending ──deny──► denied (cooldown 60 s for that plot)
pending ──30 s──► expired
pending ──requester sends another request──► replaced (only one pending request per player)
pending ──Host changes──► moves to the new Host (same expiry)
pending ──joinMode becomes 'solo' or the crew becomes full──► expired
```

`requestJoin` results by join mode:

| Join mode | Result |
|---|---|
| `open` | `joined` |
| `ask` | `pending` |
| `solo` | `closed` |

Other possible results are `full`, `cooldown`, `alreadyInCrew` and `hiddenByHost`. For
`hiddenByHost`, the client may tell the server it has hidden that player; the server then answers
"the Host is busy" without leaking that they were hidden.

## Piece (server; synced)

| Field | Type | Notes |
|---|---|---|
| id | u32 | |
| type | PieceTypeId | |
| state | 'held' \| 'flying' \| 'loose' \| 'snapped' (never synced: it is part of the tower) \| 'binned' (part of a bin) | |
| holder | sessionId \| null | |
| pos | Vec3 (cm-quantized) | loose pieces only |
| arc | { origin, velocity, t0, landing, landAt } \| null | flying pieces; included in the schema so late joiners see pieces in flight |
| touchedAt | time | fade after 60 s untouched |

**Transitions**:

| Action | Result |
|---|---|
| grab from a rack | new piece → `held` |
| grab from a bin (crew only) | bin entry → `held`; the donor gets a thanks effect |
| grab a loose piece | `loose` → `held` (the first request in the room's message order wins) |
| drop | `held` → resolve at the drop point |
| toss | `held` → `flying` (arc from shared `tossArc`) → resolve at `landAt` |

**Resolve at a point**, in this order:

1. Inside the plaza → fade at once.
2. Inside a plot's build zone, and the actor is crew → `deliver()`.
   - `snapped`, `stageComplete` or `masterpiece`: the piece is consumed.
   - `wrongPiece`: the piece is pushed out radially to 1.5 m outside the zone, and only the actor
     gets the hint.
3. Inside a build zone or bin, and the actor is not crew:
   - if the piece type is used by the blueprint and the bin has room: `binned`;
   - otherwise it is pushed out.
4. Anywhere else → `loose`.

Edge cases:

- **Crew status during a toss**: it is evaluated at landing time. A member removed while the piece
  is in flight is treated as an outsider.
- **Toss crossing a zone**: the arc's ground hit point decides. The swept segment between samples
  is tested against the zone circles so fast arcs cannot skip a zone they end in.

## Shift (server; synced; persisted)

| Field | Notes |
|---|---|
| epoch | +1 per shift; stored with every persisted row so stale rows from an old shift are ignored at boot |
| startedAt, lengthMs | default 3,600,000; set with `HHT_SHIFT_MINUTES` |
| endsAt | synced as server epoch ms; clients convert it with their measured clock offset |
| towersCompleted | |
| phase | derived by shared `shiftPhase(now, endsAt, celebrating)` |

The phases are:

```text
running ──≤ 5 min left──► warning ──≤ 30 s left──► countdown ──0──► (wait while any celebration plays) ──► resetting ──► running (epoch+1)
```

If the server boots after `endsAt` (it was down through the end of a shift), it resets immediately.
The summary sent to each player is { worldTowers, myCrewTowers, delivered, donated }.

## RateLimiter (shared `rateLimit.ts`, pure token buckets)

| Class | Refill | Burst |
|---|---|---|
| move inputs | 60/s | 12 (inputs beyond the budget are dropped: no speed hacks) |
| piece actions (grab/drop/toss) | 5/s | 8 |
| emote / quick message | 1 per 1.5 s | 3 |
| join request | 1 per 5 s | 2 |
| foreman / crew admin | 2/s | 4 |
| chat (typed) | 1 per 2 s | 3 |
| report | 1 per 10 s | 2 |

Over-limit actions are ignored and the player is sent a `slowDown` cue at most once per 2 s. **30
strikes in 10 s** (invalid plus over-limit) disconnects the client with close code 4003.

## Emote and QuickMessage (shared constants)

- **Emotes**: `wave`, `cheer`, `dance`, `point`, `thumbsUp`.
- **Quick messages**: `needBricks`, `overHere`, `thanks`, `nice`, `letsBuild`, `canIJoin`.

Only ids go over the network; the label text lives in the client. An emote or message shows for
3 s and is relayed only to players within 35 m.

## Chat (shared `chat.ts`, pure; server `systems/chat.ts`)

### ChatMessage (in flight, never stored except inside a report)

| Field | Rule |
|---|---|
| from | sender sessionId |
| channel | `'nearby'` \| `'crew'` |
| text | `sanitize()`: NFC; control, zero-width and bidi characters stripped; whitespace collapsed; trimmed; length 1–80 characters, otherwise refused with `tooLong` or `empty` |
| delivered text | `maskBlocked(text)`: matched blocklist spans → `♥` |

**Recipients**:

- **nearby**: every player within **20 m** of the sender's authoritative position when it is sent
  (the sender included, as an echo);
- **crew**: the sender's current crew members. If the sender has no crew, the result is
  `chatRefused{noCrew}`.

**Refusal reasons**, checked in order:

| Reason | Condition |
|---|---|
| `locked` | joined < 60 s ago |
| `paused` | a chat pause applies in the current epoch |
| `rate` | over the chat token bucket |
| `tooLong` / `empty` | fails `sanitize()` |
| `contact` | `detectContact()` matched |
| `duplicate` | same normalized text within 30 s |
| `noCrew` | crew channel without a crew |

### ChatReport (persisted, kept 30 days)

| Field | Notes |
|---|---|
| reporterKeyHash, reportedKeyHash, reportedName | |
| worldId, epoch, createdAt | |
| messages | JSON array of up to 5 { text, channel, at } from the reported player's `recentChat` |

**Rules**:

- A player cannot report themselves.
- Each reporter can report a given target at most once per shift; a second report gives
  `reportResult{already}`.

### ChatPause (persisted per shift)

`(worldId, keyHash, epoch, createdAt)`. It is created when there are **3 distinct**
`reporterKeyHash` values for the same `reportedKeyHash` within **10 minutes**. While
`epoch == world.epoch` it applies `chatRefused{paused}`. It is cleared implicitly by the next
shift (a new epoch). Emotes and quick messages are not affected.

## Persistence rows

See `contracts/persistence.sql`. What is persisted:

- `world`: shift, epoch and tower count;
- `building` rows, one per non-free plot;
- `crew_member` rows;
- `bin_entry` rows;
- `chat_report` rows (kept 30 days);
- `chat_pause` rows (per epoch).

Writes are synchronous and transactional on every building, crew or bin change. A restore reads
the rows whose epoch equals `world.epoch`. A restored crew member is `away` until a client joins
with the matching `keyHash`; the 120 s grace period after boot replaces the normal 60 s.
